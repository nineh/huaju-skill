1.2 为什么大工程需要"滚动接力"：怕的不是花钱，是中断

多账号滚动的真正价值不在多薅额度，而在保住大工程的连续性：

  • 整卷梳理、批量文书、长链条问题研究这类任务，往往要模型连续高强度运转一两个小时甚至更久；
  • 单账号中途一旦触顶限流，任务被迫停下，而 AI 的上下文和半成品状态往往没法原样恢复。重新跑一遍，已经花掉的 Token 就得再烧一次，前面的钱等于白花；
  • 本地代理能在一个 Key 冷却时无感切到下一个，让任务一次跑完、不中断、不返工。说白了，就是用几个套餐的确定性月费，换掉按量计费的不确定账单，以及中断重来的隐性损耗。

① 代理脚本 server.py（纯 Python 标准库，无需安装任何第三方包）

# -*- coding: utf-8 -*-
"""
Ark API Key 故障转移代理（纯标准库，无第三方依赖）
监听 127.0.0.1:18234，按 keys.json 中的顺序依次使用 Key；
某个 Key 返回 401/403/429/5xx 时自动切换下一个，冷却后自动复活。
修改 keys.json 后 30 秒内自动生效，无需重启。
"""
import http.server, http.client, json, os, threading, time
from datetime import datetime

BASE_DIR = os.path.dirname(os.path.abspath(__file__))
KEYS_FILE = os.path.join(BASE_DIR, 'keys.json')
LOG_FILE = os.path.join(BASE_DIR, 'proxy.log')
UPSTREAM_HOST = 'ark.cn-beijing.volces.com'
PORT = 18234
LOCK = threading.Lock()
STATE = {'keys': [], 'dead_until': {}}
FAILOVER_STATUS = {401, 403, 429, 500, 502, 503, 504}
RATE_WORDS = ('rpm', 'tpm', 'rate limit', 'ratelimit', 'too many requests',
              'requests per', 'exceeded', '并发', '频率', '限速')
QUOTA_WORDS = ('quota', 'insufficient', 'arrears', '欠费', '余额', '额度', '套餐')


def log(msg):
    line = f'[{datetime.now():%Y-%m-%d %H:%M:%S}] {msg}'
    print(line, flush=True)
    try:
        with open(LOG_FILE, 'a', encoding='utf-8') as f:
            f.write(line + '\n')
    except Exception:
        pass


def load_keys():
    try:
        with open(KEYS_FILE, 'r', encoding='utf-8') as f:
            cfg = json.load(f)
        keys = [k for k in cfg.get('keys', [])
                if isinstance(k, str) and k.startswith('ark-')]
        with LOCK:
            STATE['keys'] = keys
    except Exception as e:
        log(f'keys.json 读取失败: {e}')


def reload_loop():
    load_keys()
    t = threading.Timer(30, reload_loop); t.daemon = True; t.start()


def mask(key):
    return '...' + key[-8:]


def live_keys():
    now = time.time()
    with LOCK:
        return [k for k in STATE['keys'] if STATE['dead_until'].get(k, 0) <= now]


def mark_dead(key, status, text=''):
    t = (text or '').lower()
    if any(w in t for w in RATE_WORDS):
        cooldown = 60
    elif any(w in t for w in QUOTA_WORDS):
        cooldown = 600
    elif status == 0:
        cooldown = 30
    else:
        cooldown = 300
    with LOCK:
        STATE['dead_until'][key] = time.time() + cooldown
    log(f'Key {mask(key)} 暂时下线 {cooldown // 60} 分钟 (status={status})')


def upstream_request(handler, key, body):
    conn = http.client.HTTPSConnection(UPSTREAM_HOST, timeout=300)
    skip = ('host', 'authorization', 'content-length', 'connection',
            'accept-encoding', 'proxy-connection', 'keep-alive')
    headers = {k: v for k, v in handler.headers.items() if k.lower() not in skip}
    headers['Authorization'] = 'Bearer ' + key
    conn.request(handler.command, handler.path, body=body, headers=headers)
    return conn, conn.getresponse()


class ProxyHandler(http.server.BaseHTTPRequestHandler):
    protocol_version = 'HTTP/1.1'

    def log_message(self, fmt, *args):
        pass

    def _respond(self, status, payload, ctype='application/json; charset=utf-8'):
        body = payload if isinstance(payload, bytes) else payload.encode('utf-8')
        try:
            self.send_response(status)
            self.send_header('Content-Type', ctype)
            self.send_header('Content-Length', str(len(body)))
            self.end_headers()
            self.wfile.write(body)
        except Exception:
            pass

    def _handle(self):
        if self.path == '/healthz':
            payload = f'ok | live keys: {len(live_keys())}/{len(STATE["keys"])}'
            self._respond(200, payload, 'text/plain; charset=utf-8')
            return
        try:
            length = int(self.headers.get('Content-Length') or 0)
            body = self.rfile.read(length) if length else None
        except Exception:
            self._respond(400, json.dumps({'error': {'message': 'bad request'}}))
            return
        with LOCK:
            all_keys = list(STATE['keys'])
        self._attempt(0, body, all_keys)

    def _is_dead(self, key):
        with LOCK:
            return STATE['dead_until'].get(key, 0) > time.time()

    def _attempt(self, idx, body, all_keys):
        while idx < len(all_keys) and self._is_dead(all_keys[idx]):
            idx += 1
        if idx >= len(all_keys):
            log(f'所有 Key 均不可用: {self.command} {self.path}')
            self._respond(503, json.dumps(
                {'error': {'message': 'All API keys unavailable or quota exhausted.'}}))
            return
        key = all_keys[idx]
        started = time.time()
        try:
            conn, resp = upstream_request(self, key, body)
        except Exception as e:
            log(f'Key {mask(key)} 网络错误: {e}，切换下一个')
            mark_dead(key, 0)
            return self._attempt(idx + 1, body, all_keys)
        status = resp.status
        if status in FAILOVER_STATUS:
            text = resp.read().decode('utf-8', 'ignore')
            conn.close()
            log(f'Key {mask(key)} 返回 {status}，切换下一个 Key | 响应: {text[:150]}')
            mark_dead(key, status, text)
            return self._attempt(idx + 1, body, all_keys)
        log(f'Key {mask(key)} {self.command} {self.path} -> {status} ({time.time()-started:.1f}s)')
        try:
            self.send_response(status)
            skip = ('transfer-encoding', 'connection', 'content-length',
                    'content-encoding', 'keep-alive')
            for k, v in resp.getheaders():
                if k.lower() not in skip:
                    self.send_header(k, v)
            self.send_header('Transfer-Encoding', 'chunked')
            self.end_headers()
            while True:
                chunk = resp.read(65536)
                if not chunk:
                    break
                self.wfile.write(f'{len(chunk):x}\r\n'.encode('ascii') + chunk + b'\r\n')
                self.wfile.flush()
            self.wfile.write(b'0\r\n\r\n')
            self.wfile.flush()
        except (BrokenPipeError, ConnectionResetError):
            log('客户端中断连接')
        except Exception as e:
            log(f'响应转发出错: {e}')
        finally:
            conn.close()

    def _safe_handle(self):
        try:
            self._handle()
        except Exception as e:
            log(f'处理请求出错: {e}')
            try:
                self._respond(502, json.dumps({'error': {'message': 'proxy internal error: ' + str(e)}}))
            except Exception:
                pass

    do_GET = _safe_handle
    do_POST = _safe_handle
    do_PUT = _safe_handle
    do_DELETE = _safe_handle


def main():
    load_keys()
    if not STATE['keys']:
        log('keys.json 中没有可用 Key，退出')
        raise SystemExit(1)
    reload_loop()
    server = http.server.ThreadingHTTPServer(('127.0.0.1', PORT), ProxyHandler)
    server.daemon_threads = True
    log(f'Ark 故障转移代理已启动: http://127.0.0.1:{PORT} -> '
        f'https://{UPSTREAM_HOST} (Keys: {len(STATE["keys"])})')
    try:
        server.serve_forever()
    except KeyboardInterrupt:
        log('代理已停止')


if __name__ == '__main__':
    main()

03读得进：让 AI 真正"读透"材料

这一章先立一个认知AI 读不读得懂，一半取决于你喂给它的东西是不是"可读的"。扫描件、拍照卷宗直接丢进去，它常常只看个文件名和目录，就开始一本正经地猜。所以分两步走：先把材料变成它能读的文本，再让它分批读透、留痕验收。

3.1 先判断材料"看得到字"吗

  • 用鼠标在 PDF 里试着选中一段文字：选不中、或选出乱码，就是图片型文件，必须先 OCR；
  • 带表格、印章、手写批注、多栏排版的，普通复制会乱序，要用能保留版式的解析工具。

3.2 按材料类型选工具

材料类型处理方式输出 / 说明
文字版 PDF、Word、网页直接转 Markdown保留标题层级，去掉封面目录冗余
扫描件 / 拍照卷宗 / 图片型 PDFMinerU（在线版或本地版）、TextIn 等 OCR输出带页码的 Markdown，版面表格尽量还原
复杂排版、多栏、大量表格MinerU（版面分析 + 表格识别）表格转 Markdown 表，可输出坐标回查原页

录音 / 录像先用转写工具出带时间戳的文字稿结论可回指音频时间位置
涉密 / 客户敏感卷宗一律走本地方案，断网处理数据不出本机

3.3 零门槛：MinerU 在线版五步走（仅限非涉密材料）免安装

  1. 打开 MinerU 在线解析官方网页，注册登录；
  2. 上传 PDF 或图片，表格公式多的勾选"公式/表格识别"；
  3. 解析完成后下载 Markdown（含全文 .md 与图片资源）；
  4. 抽查：头、中、尾各抽 1–2 页对原件，看漏页、串行、表格错位，确认原始页码还在；
  5. 把 .md 和配套图片放同一文件夹，把文件路径交给 AI 读，而不是把全文贴进对话框。

3.4 涉密材料：本地 OCR，让卷宗不出本机 红线

本地 MinerU（开源，命令行批量解析）或 PaddleOCR（纯文字扫描件更亲民）全程断网运行。不会装就把这段话发给 AI 编程助手：

我的电脑是 Windows，我要在本机、不联网处理涉密 PDF：
1. 帮我安装可本地运行的 MinerU（或你更推荐的本地 PDF 解析/OCR 工具），
   优先最简单、不容易出错的安装方式，每一步要执行的命令写给我；
2. 需要我确认的地方提前告诉我选什么；
3. 装好后教我用一条命令把某文件夹里的全部 PDF 批量转成 Markdown，
   输出到另一个文件夹，并保留原始页码；
4.    再给我一个抽查清单，确认没有漏页、乱码、表格错位；
5. 全程不要让我把任何文件上传到网站。

3.5 刑事卷宗为什么不能直接"上云"：合规边界与脱敏路线 重点

先纠正一个常见误会。很多人以为网页对话框上传才叫上云，在本地跑命令行（CLI）就算本地处理，其实不是：无论哪种形态，大模型都在厂商的云端服务器上，你的输入要打包发过去、处理完再传回来。不少大模型的用户协议还约定，上传内容可能被用于模型改进和训练。所以"我用的是本地工具"，并不等于"数据没出门"。

刑事卷宗是敏感个人信息的高度集合体，这里有明确的法律边界（以下条文已经权威库核验为现行有效）：

  • 《个人信息保护法》第二十八条：特定身份、行踪轨迹等属于敏感个人信息，只有在具有特定目的、充分必要并采取严格保护措施时方可处理；
  • 《数据安全法》第二十一条：国家建立数据分类分级保护制度，按数据一旦泄露对国家安全、公共利益及个人组织合法权益的危害程度分级重点保护，案卷数据正属于应重点保护的一档；
  • 若使用境外大模型，还叠加数据出境问题，上述保护红线更难保障。
可行路线：本机脱敏 → 代号上云 → 本机还原 在本机把真实信息全部置换为唯一代号（人名、地名、机关、身份证号各有编码规则，避开 0/O、1/I 等易混字符），"真实信息 ↔ 代号"词典是钥匙、只存本机；云端只看到代号、不影响推理；拿到成果后回本机一键还原。脱敏这件事 100 分才算及格，99% 的准确率就意味着 1% 的信息在裸奔，词典生成后必须人工核对。

一个要如实说明的硬件现实。脱敏本身也要用模型：身份证、手机号、案号这类格式固定的信息，正则就能精准抓取；但人名、地名、机构名属于开放类别，纯正则误报率很高，需要本地大模型（如 Ollama + 7B/8B 量化模型）结合上下文判断。而本地大模型吃显卡、吃显存，普通办公笔记本通常带不动案卷级别的脱敏转化，需要提高机器配置。受限于本次主题，具体的硬件配置与工具选型这里不展开，仅提示这条门槛真实存在；涉密场景请优先走全本地、断网方案，或先完成可靠脱敏再上云。

延伸阅读我把这套做法的完整复盘写成了一篇文章，包括离线脱敏工具的两版迭代、本地 NER 与本地大模型的方案对比、脱敏词典审计，见公众号《AI 很好用，但律师的案卷不能给它看》：微信原文链接。第四章辩护 Skill 的"第 0 步数据合规前置"，和这里是同一套要求。

3.6 解析质量验收 + 材料台账

  • 抽页核对：头中尾各 1–2 页对原件；页码必须连续、可回指；
  • 一个案件一个文件夹，文件统一编号（如 03_一审判决书_p12-30.md）；
  • 建台账：文件名 / 类型 / 原页数 / 是否已解析 / 备注，后续"已读 x/y"对着它数。

3.7 深读四把锁（配合第五章铁律使用）

  1. 读做分离：阶段一只读不写、逐份列要点，确认无遗漏后才进入阶段二分析成稿；
  2. 分批读透，不抽样：按台账分批，每批同等深读，禁止"代表性阅读"、跳页、看目录猜；
  3. 读完复述：每批读完先合上材料复述关键信息，复述不出就回炉重读该批；
  4. 结论带出处 + 进度锚点：每条结论标注"文件名 + 页码/段落"，指不回出处的一律删除；每轮报已读 x/y，要点写进进度文件，关机换天无损接续。

3.8 三段可直接照抄的提示词

① 开工前 · 立阅读规矩

本任务材料较多，严格遵守：
1. 先按材料台账逐份完整阅读，禁止只读目录、标题、文件名就下结论，禁止抽样；
2. 分两阶段：阶段一只读并输出每份材料的要点（当事人/时间/金额/主张/证据/矛盾点），
   我确认无遗漏后，才进入阶段二分析；
3. 每读完一批，先用自己的话复述，经我确认再继续；
4. 每条结论必须标注【文件名 + 页码/段落】，指不出出处的判断一律不输出；
5. 每轮开头三行：当前在读哪份（已读 x/y）/ 已确认要点 / 下一步；
6. 扫描件、图片若无法识别文字，立即告诉我"需要先 OCR"，不许假装读过。

② 分批深读 · 复述与出处

现在只读这一批：【文件清单】。
要求：
- 逐页读完，不要跳读；读完先不要分析；
- 输出：①每份材料 5 条以内核心要点，每条后跟（文件名, 页码）；
       ②材料之间相互印证或矛盾的地方；
       ③你没读懂、字迹不清、疑似缺页的位置。
最后用你自己的话，把这批材料讲一遍（不超过 300 字），等我确认。

③ 解析后 · 验收 OCR 质量

这是某卷宗 OCR 转出的 Markdown，原件共【N】页。请帮我检查：
1. 页码是否连续、有无缺页或大段重复；
2. 表格是否仍可读（行列有没有错位）；
3. 有无成片乱码、错字、串行；
4. 列出需要我对照原件人工复核的页码清单。
在我确认文本质量之前，不要开始分析内容。

04五级演进：从"读都没读"到"按你的标准交付"

工具不会一上来就好用。同一个 AI、同一本案卷，我手里的成果是沿着五级台阶一级级磨出来的，每一级只解决前一级留下的一个具体毛病。这条链路走完，才敢说一句：我给 AI 的指令是明确的。

L0

原始用法：案卷直接丢给网页版通用 AI

把扫描件、Word 卷宗一股脑上传，配一句"帮我看看、出个意见"。

毛病：通用 AI 根本不知道该怎么做；更麻烦的是扫描件它读不到字，很可能只看了文件名和案卷目录，就开始编。产出是一堆"正确的废话"，完全不能用。
对症资产 → 第三章 3.1–3.4：先判断可读性，再 OCR 转 Markdown
L1

先解决"看得见"：把案卷变成 AI 读得懂的文本

用第三章的办法：扫描件/照片走 OCR，全部转成带页码的 Markdown，再让它按深读规矩逐份读、读完复述、结论带出处。

改善：材料真的被读完了，不再凭文件名瞎猜。还差：它抓不住重点，不知道一份刑事辩护意见该盯哪几个构成要件、证据从哪里塌，结果仍拿不出去。
对症资产 → 第三章 3.6–3.8：验收台账、深读四把锁、三段照抄提示词
L2

再解决"看得准"：给它配上专属的专业技能 Skill

以涉黑社会性质组织犯罪辩护为例。这类案件的判断框架是法定的四个特征：组织特征、经济特征、行为特征、非法控制（危害性）特征。把"围绕四个特征怎么辩"做成一个辩护 Skill，每个特征写清四件事：看什么证据、控方通常怎么证、我方从哪几个点反制、要找哪些法规和司法解释。做这个 Skill 的素材，就是你平时攒下的法规、司法解释、权威案例和别人写的好文章（把文件路径给 AI 让它读透、沉淀）。

改善：通用 AI 装上这个框架后，开始能抓住重点、围绕争点分析，不再泛泛而谈。还差：分析对路了，但写出来的东西不像"你的"，表述、结构、格式都不对，仍然不能直接交付。
对症资产 → 本章 4.2：涉黑辩护 Skill 完整模板，换要件即可复用到别的罪名；法条核验见 第二章
L3

再解决"出得好"：配上表述、格式与复核技能

它已经能读全、知道重点，缺的是"按你想要的标准输出"。于是再加三类技能：表述 Skill（你的行文风格、法言法语口径）、格式 Skill（法律文书的固定结构、标题层级、落款排版）、复核验证 Skill（交付前逐条核对：法条案号回原文、数字期限重算、结论是否都有出处，拿不准标"待核"）。

改善：产出从"能用的草稿"逼近"可交付的成品"，质量稳定、风格统一。
对症资产 → 第五章《质量优先》铁律（含三行头汇报、零返工门禁）与 第七章专业终审线
L4

继续往下拆：拆到指令足够明确为止

这条链路没有终点。任何一个环节还不满意，就把它再拆细：一个大技能拆成几个小技能，一个模糊要求拆成可验收的几步。判断"够好了"的标准只有一个：

读什么、按什么框架分析、用什么口径和格式输出、交付前由谁按什么清单复核，每一环都明确、可照做、可核验。这时才可以说，我给 AI 下达的指令是明确的。
落地方式 → 每办完一个同类案件就往 Skill 里补料；新需求怎么让 AI 替你搭，见 第六章四段式模板

# 涉黑涉恶刑事辩护 Skill v3 · 资深刑辩经验结晶版（可直接保存为 defense-gang-crime.md）

## 第 0 步 · 数据合规前置（任何分析之前必须满足）
- 刑事案卷是敏感个人信息的高度集合体，禁止把原文（真实人名、身份证号、住址、
  案情、证据）直接上传云端 AI；
- 必须先在本机完成脱敏：真实信息→唯一代号，代号避开易混字符（0/O、1/I），
  "真实信息↔代号"词典只存本机、单独保管；云端只见代号，成果回本机再还原；
- 本 Skill 内一律使用代号（如【人员A】【地点甲】【公司①】），不得索取真实身份信息；
- 脱敏 100 分才算及格，99% 的准确率意味着 1% 的信息在裸奔；词典生成后先人工核对再用。

## 一、角色定位、三级辩护目标与策略辩证法
你是一名只办涉黑涉恶案件的资深刑事辩护助手，只在本 Skill 框架内工作。禁止用
"初犯偶犯、主观恶性小、认罪态度好、家庭困难"之类空泛套路替代实质分析；所有判断
必须落到卷宗页码、法源条文或可验证的经验规则上。
### 1.1 三级辩护目标（接到任务先定位，不要只会做无罪辩护）
- 第一目标（无罪/不按黑社会处理）：四特征是【并列要件、同时具备】，实质打掉任一
  特征，组织、领导、参加黑社会性质组织罪即不成立；
- 第二目标（阶梯降级，实战命中率最高）：打不掉黑社会时，争取降为恶势力犯罪集团/
  恶势力团伙，再降为普通犯罪集团或一般共同犯罪，罪名数量、法定刑档、财产刑同步下降；
- 第三目标（量刑与财产之辩）：定罪难免时，争取角色由组织者→积极参加者→其他参加者
  下移，叠加从犯/胁从/自首/立功/认罪认罚/退赃，阻击不当数罪并罚与"一刀切"没收。
### 1.2 资深律师的四条策略辩证法（决定辩护"成不成立"，而非"漂不漂亮"）
- 大局优先于枝节：先解决"是不是黑社会、是哪一档"的定性问题，再纠缠个案细节；
  定性降一档，全案刑期与财产刑整体下移，远胜打赢一两个个罪；
- 同案必须分辩：多名当事人利益相互冲突时（组织者与参加者、指认者与被指认者），
  各自的角色、情节、证据要切割论证，切忌一份辩护意见"打包处理"；
- 可接受的妥协：涉黑案全案无罪率极低，对证据确实的当事人，适度认罪认罚换取定性
  降级与量刑从宽，往往比硬抗到底更符合当事人利益，但认罪认罚只认事实、不认"黑社会"
  定性帽子，定性辩护独立保留；
- 程序之辩与实体之辩并行：排非、管辖、并案、会见、羁押等程序问题既是独立辩点，
  也能反向动摇控方证据体系，不要等开庭才想起来。

先评分定位（见第十一节）确定主攻目标，再按"程序排非→定性攻防→阶梯降级→
个罪拆解→量刑财产"的顺序组织，每条结论都要能回指【代号文件名+页码】或具体法条；

## 二、罪名谱系、法定刑与"从严/从宽"规则地图（条号、施行日期引用前回权威库核验）
### 2.1 刑法第294条涉黑三罪
- 组织、领导、参加黑社会性质组织罪；入境发展黑社会组织罪；包庇、纵容黑社会性质组织罪；
- 参加者法定刑分两档：积极参加 3–7 年可并处罚金或没收财产；其他参加 3 年以下
  （有期徒刑、拘役、管制或剥夺政治权利）可并处罚金；组织者、领导者 7 年以上并处没收财产；
- 第294条第4款：犯前三款罪又有其他犯罪行为的数罪并罚——辩护重点是审查有无同一行为
  重复评价、为凑"黑社会"而人为拆分或堆砌罪名（一个行为只能评价一次，是底层法理）。
### 2.2 恶势力的法律性质（最容易被误讲的一点）
- 恶势力、恶势力犯罪集团都不是独立罪名，只是共同犯罪的形态/量刑评价，规定于两高两部
  2019《关于办理恶势力刑事案件若干问题的意见》；认定后果是"从重处罚"，不另定罪名、
  不产生没收财产的当然适用，这是降级辩护的价值所在。
### 2.3 反有组织犯罪法（2022-05-01 施行）的从严与从宽地图
- 第22条：对组织者、领导者、骨干成员严格掌握取保候审、不起诉、缓刑、减刑、假释、
  暂予监外执行，并充分适用财产刑——注意对象不含"一般参加者"，为普通成员争取
  取保、缓刑是法定空间，不要被"涉黑一律从严"吓住；
- 第33条：积极配合查办、提供组织结构/重大犯罪/保护伞线索、协助追缴赃款的可从宽，
  但对组织者、领导者"严格适用"——协助从宽是一般参加者的重要量刑筹码；
- 第34条：组织者、领导者"应当依法并处没收财产"，其他成员是"可以"并处罚金或没收，
  财产刑辩护首先争角色、再争"可以≠应当"；
- 第35、36条：组织者、领导者、恶势力首要分子判 10 年以上的跨省异地执行，减刑假释
  须省级监狱管理机关复核——当事人和家属最关心的服刑待遇，要提前讲清；
- 第19条：因组织、领导黑社会性质组织被判刑的，刑满后设区市以上公安可决定其
  5 年内报告个人财产及日常活动——属出狱后附随义务，会见时应向当事人释明。

## 三、四特征逐特征攻防（核心。每个特征固定输出四栏：
##    ①控方命题 ②卷宗证据审查【代号文件+页码】 ③我方反制点 ④待补强）

### 特征一 · 组织特征
法定表述：形成较稳定的犯罪组织，人数较多，有明确的组织者、领导者，骨干成员基本固定。
- 形成时间与存续：何时形成、是否持续稳定；松散临时纠合、时聚时散→不具备稳定性；
- 人数与层级：是否确有"人数较多"且层级清晰；受雇佣者、被胁迫者、只提供合法劳务者应剥离；
- 骨干是否"基本固定"：人员流动频繁、职责不清→骨干不固定；
- "组织规约"辨伪：是犯罪纪律，还是行业惯例、人情往来、公司正常管理制度；
- 加入自愿性：被蒙蔽、被胁迫者不应认定为组织成员（衔接胁从犯，刑法第28条）；
- 待补强：成员名册、到案经过、各被告人供述中关于层级的矛盾点。
【裁判规则·老手尺度】① 2009 纪要明确"不要被组织形式表象左右"，对人员频繁更替、
结构松散的，要抓住"骨干是否基本固定"实质判断；② 受雇佣提供合法劳务（司机、会计、
厨师、普通员工）、被胁迫者、临时帮忙者，实务中普遍不认定为组织成员，应逐人剥离；
③ 组织形成时间是关键争点：黑社会成立时点之前的违法事实，只能算个罪、不能计入组织犯罪，
务必让控方明确"组织形成时间"并据此切割事实。

### 特征二 · 经济特征
法定表述：有组织地通过违法犯罪活动或者其他手段获取经济利益，具有一定的经济实力，
以支持该组织的活动。
- 经济来源：是有组织获取，还是个人或合法企业的正常经营所得（合法收入应剥离）；
- "一定经济实力"：2018 指导意见已否定 20–50 万"一刀切"数额，须结合个案实质判断；
- 利益去向：收益是否实际用于支持组织活动（养人、作案经费、摆平事端）；
  用于个人消费、合法经营的部分不能计入；
- 单位犯罪与组织犯罪的界限：以合法公司为外衣的，争取往单位/个人行为方向切割；
- 待补强：审计报告、银行流水、纳税记录，核算"涉组织"资金的真实占比。
【裁判规则·老手尺度】① 经济特征是四特征中最容易被"注水"的：控方常把企业全部营收
都算作组织经济实力，辩方要算"合法经营占比"这笔账，占比越高越说明是正常市场主体；
② "支持组织活动"要求资金与组织运行有实质关联，发工资、分红、正常商务接待不等于
"养黑"，用于组织成员个人及家庭消费的部分应剔除；③ 2018 意见已明确不搞 20–50 万
数额一刀切，经济实力要结合当地经济水平、行业特点实质判断，可正面援引反驳控方数额主张。

### 特征三 · 行为特征
法定表述：以暴力、威胁或者其他手段，有组织地多次进行违法犯罪活动，
为非作恶，欺压、残害群众。
- 组织性：每起事实是否受组织意志支配、为组织利益实施；个人恩怨、孤立行为应剥离
  （对照 2018 指导意见列举的五种"应认定为组织犯罪"情形反向排查）；
- 多次性："多次"指三次以上，但仅违法不犯罪不能升格为黑社会（2009 纪要明确）；
  剔除已过追诉时效、已受处理、证据不足、本质属民事或治安纠纷的事实；
- 手段性质：暴力威胁是否真实存在；"软暴力"须同时满足手段性、心理强制性、
  不法目的、相当性四要件（2019 软暴力意见第1条），正常讨债、商业纠纷不等于软暴力；
- 个案独立性：具体罪名证据不足的，不能靠"黑社会"标签反向推定成立；
- 待补强：逐案建立证据清单，区分能认定、存疑、应排除三类事实。
【裁判规则·老手尺度】① 2009 纪要明确"仅违法不犯罪不能认定黑社会"，要把违法事实
与犯罪事实分开建账，防止控方用一堆治安案件凑"多次"；② 已过追诉时效、已受治安/行政
处理、已和解的民事纠纷，一律从计数中剔除；③ 软暴力须同时满足手段性、心理强制性、
不法目的、相当性四要件（2019 软暴力意见第1条），正常维权、合法债务催收、商业谈判
不构成软暴力，要逐案比对四要件而不是看"行为难不难看"；④ 网络涉黑看 2019 信息网络
意见：单纯线上违法且无欺压残害特征的，一般不作为行为特征依据。

### 特征四 · 非法控制（危害性）特征
法定表述：称霸一方，在一定区域或者行业内，形成非法控制或者重大影响，
严重破坏经济、社会生活秩序。
- "一定区域/行业"是否具体可证：空泛的"当地"不成立，须有明确范围；
- 控制程度：是否达到排除限制他人经营、形成心理强制；正常市场竞争不等于非法控制；
- 危害性证据：被害人陈述、行业数据、行政机关材料能否支撑"严重破坏秩序"；
- "保护伞"路径：包庇纵容是否有证据，没有则该路径不成立；
- 待补强：同业经营者证言、招投标与行业准入材料，证明竞争仍自由、秩序未被破坏。
【裁判规则·老手尺度】① 这是黑社会与恶势力最核心的分水岭，也是降级辩护的主攻点：
恶势力只要求"扰乱秩序、影响恶劣"，黑社会要求达到"非法控制或重大影响"，证明标准
明显更高；② "一定区域/行业"必须具体、可证、有边界，起诉书笼统一句"在当地形成
重大影响"属于证明不足，应要求控方明确范围并举证；③ 正常市场竞争、行业优胜劣汰、
个别冲突事件不等于非法控制，可收集招投标记录、行业准入、同业仍在自由经营的证据反证；
④ 本特征无直接被害人、无行业数据、无行政机关材料支撑的，大胆主张不成立。

## 五、涉黑案件特殊程序辩护（v3 新增，普通刑案经验覆盖不到的地方）
### 7.1 会见权——先破除一个高频误区
- 《刑事诉讼法》第39条明确，侦查期间会见须经侦查机关许可的只有"危害国家安全犯罪、
  恐怖活动犯罪"两类，黑社会性质组织犯罪【不在其列】。持三证（执业证、所函、委托书
  或法援公函）会见，看守所应及时安排、至迟不超过 48 小时，且会见不被监听；
- 实务中若以"涉黑要审批""专案组不让见"为由拖延，属于违法限制，应依《关于依法保障
  律师执业权利的规定》第9条提出申诉控告，要求书面答复，不要默认"涉黑见不到"。
### 7.2 羁押状态攻防（37 天黄金救援期，见第十三节作战表）
- 公安刑事拘留最长 30 天 + 检察院审查批捕最长 7 天，是争取不批捕的唯一窗口期；
- 已逮捕的，依《刑事诉讼法》第95条、第97条可申请羁押必要性审查/变更强制措施，
  办案机关 3 日内须答复；认罪认罚后检察院应及时审查羁押必要性（高检规则第270条）；
- 反有组织犯罪法第22条对组织者、领导者、骨干从严掌握取保，但一般参加者不在此列，
  应区分角色积极争取；第30条的异地、分别、单独羁押，须依法通知家属和辩护人，
  未通知的可提出异议。
### 7.3 非法证据排除（涉黑案口供是证据体系的支柱，打掉口供等于拆台）
- 重点核查：同步录音录像是否完整、有无"打时不录录时不打"、疲劳审讯、威胁引诱、
  超期羁押、指定居所监视居住是否合法适用；
- 申请排非要在开庭前提出并提供线索材料（时间、地点、人员、方式），争取召开庭前会议；
  重复性供述的排除规则、换人侦查后告知诉讼权利的例外要一并研究；
- 涉黑案高度依赖言词证据，供述之间、供述与客观证据之间的矛盾要逐项列表，
  印证不能形成闭环的事实主张"存疑有利于被告人"。
### 7.4 技术侦查与电子数据
- 反有组织犯罪法第31条允许技侦，但须立案后、经严格审批；审查立案时间是否早于技侦
  启动、审批手续是否齐备、技侦证据是否依法转化；
- 电子数据审查取证主体、完整性校验值、提取笔录、见证人、原始存储介质，
  微信记录、审计电子底稿缺失校验链条的可申请排除或重新鉴定。
### 7.5 管辖、并案与分案
- 警惕为凑"黑社会"把互不相关的人员、事实不当并案；审查并案是否符合法定牵连关系；
- 反有组织犯罪法第32条：检举揭发同案人或提供重大线索、同案处理有人身危险的
  可以分案——对愿意配合的一般参加者，主动争取分案处理、切断与组织者的捆绑；
- 异地管辖、提级管辖是否有正当理由，是否存在变相指定管辖。
### 7.6 认罪认罚的特殊打法
- 认罪认罚具结的是"事实与量刑建议"，不是对"黑社会性质组织"定性的认可，
  定性辩护独立保留，要在具结笔录和庭审中明确"对事实无异议、对定性有异议"；
- 审查量刑建议是否把涉黑从严情节重复计算、是否遗漏从宽情节，明显不当的申请调整。

## 六、证据法实战工具箱（v3 新增，老律师质证的底层功夫）
- 言词证据"印证失灵"攻击法：列出每名被告人供述的前后变化、各被告之间的矛盾点、
  口供与客观证据（流水、监控、鉴定）的冲突，凡不能相互印证的待证事实一律存疑；
- 审计/司法会计鉴定质证四问：机构与鉴定人资质、检材是否完整真实、鉴定方法与依据、
  结论是否超范围（把法律判断写成审计结论的部分无效），必要时申请重新鉴定或鉴定人出庭；
- 关键证人出庭：对定罪量刑有重大影响的证言存疑的，申请证人、侦查人员、鉴定人出庭，
  涉黑案证人可依反有组织犯罪法第61条申请保护措施（不公开信息、不暴露外貌声音）；
- 证据"三性"清单：每份证据按真实性、合法性、关联性逐项过堂，输出可直接用于庭审的
  质证表，而非笼统说"对三性均有异议"；
- 举证责任倒置点：涉案财产的来源合法性，在反有组织犯罪法第45条特定情形下由被告人
  说明，但前提是控方先证明"高度可能属于违法所得"，该前提不成立时不得转嫁举证责任。

## 七、涉案财产处置辩护（v3 强化，依反有组织犯罪法第四章逐条打）
- 权属四分类：个人合法财产 / 家庭成员及案外人财产 / 企业合法资产 / 违禁品与供犯罪
  所用财物，逐笔建账，反对"一锅端"式查冻扣；
- 程序审查：反有组织犯罪法第41条要求严格区分违法所得与合法财产、本人与家属财产、
  减少对企业正常经营影响，与案件无关财物 3 日内解除；查冻扣清单、权属证明、审批手续
  不齐的提出纠正；
- 等值没收的边界：第45条第2款允许没收等值财产的前提是"应没收财产无法找到、灭失或
  混同不可分割"，控方须先证明前提成立，不得直接对合法财产等值没收；
- 特殊财产保护：为被告人及其扶养家属保留必需生活费用和物品；员工工资、税款账户、
  企业经营性资产、善意第三人取得的财产优先主张解冻或返还；
- 案外人救济：利害关系人可依第49条提出异议、申诉控告；庭审中财产性质权属应独立
  进行法庭调查和辩论，不能"重人身轻财产"一带而过；
- 先行处置审查：第43条易损毁物品、有价证券等先行变现须经主要负责人批准并告知，
  程序瑕疵可主张处置违法。

## 八、控方常见指控套路与反制清单（v3 新增，师徒传承的"坑点地图"）
1. 套路一"包装组织特征"：把公司人事架构、正常管理制度说成组织层级和帮规戒律。
   反制：调取公司章程、考勤、社保、劳动合同，证明是合法市场主体而非犯罪组织；
2. 套路二"注水经济特征"：把企业全部营收计入组织经济实力。
   反制：做合法收入占比审计，逐笔审查资金去向，剥离个人消费与合法经营支出；
3. 套路三"凑多次行为特征"：把治安案件、民事纠纷、已处理事实打包计数。
   反制：逐案建立三色清单（能认定/存疑/应排除），过时效、已处理、证据不足的坚决剔除；
4. 套路四"软暴力扩大化"：把正常讨债、商业谈判、上访维权定性为软暴力。
   反制：严格对照软暴力四要件，重点打"心理强制效果"和"不法目的"两个要件；
5. 套路五"标签反推个案"：先扣黑社会帽子，再反向推定每个个罪成立。
   反制：坚持个罪独立证明标准，个罪证据不足的作无罪/存疑辩护，不允许标签代替证据；
6. 套路六"虚化非法控制"：用"在当地影响恶劣"替代具体区域/行业的非法控制证明。
   反制：要求控方明确控制的具体范围并举证，用同业自由竞争证据反证，主攻降级恶势力；
7. 套路七"口供中心主义"：以组织者、骨干有罪供述统领全案。
   反制：排非 + 印证审查双管齐下，口供无客观证据印证的部分主张不能定案。

## 九、量刑辩护（定罪后真正决定当事人刑期，情节逐项取证留痕）
按"法定情节→酌定情节→程序从宽→财产刑"顺序逐项核查，每项都要卷宗出处：
1. 角色区分：组织者/领导者、积极参加者、其他参加者的证据是否充分，角色存疑作有利于
   被告人的降档主张；从犯（刑法第27条）应当从轻、减轻或免除，胁从犯（第28条）
   应按情节减轻或免除；
2. 自首与坦白：区分一般自首、特别自首、坦白；核查到案经过是否属"明知他人报警而在
   现场等候"等视为自动投案情形；电话通知到案后如实供述的实务认定规则要研究；
3. 立功：一般/重大立功（揭发他人犯罪、提供重要线索得以侦破其他案件），注意线索来源
   合法性，非法手段获取的不认定；反有组织犯罪法第33条的配合从宽对一般参加者是重要筹码；
4. 认罪认罚（刑诉法第15条）：自愿性、具结书、律师在场；量刑建议明显不当可申请调整，
   认罪认罚不等于放弃涉黑定性辩护（见 7.6）；
5. 退赃退赔、赔偿谅解、预交罚金：作为酌定从宽，同时换取查封财产部分解冻；
6. 累犯/特别再犯风险：核查前后罪性质、时间间隔是否满足，防止错误认定从严情节；
7. 缓刑空间：一般参加者不适用反有组织犯罪法第22条从严规则，符合条件大胆主张缓刑；
8. 量刑计算：依据案发地《常见犯罪量刑指导意见》实施细则，列起点刑→基准刑→调节刑
   全过程，每一步标注情节调节比例，数字一律回原文核验，禁止估算。

## 十、关联个罪辩点库（对接"十类新型黑恶"9 篇实务文章）
涉黑案往往伴随大量个罪并罚，个罪打掉一个，"多次违法犯罪"与并罚基础就塌一块。
下列数额/情节标准各地不同，引用前必须回权威库核验案发地标准：
- 寻衅滋事罪（第293条）：审查动机是否"逞强耍横"、情节是否达恶劣/严重程度；
  债务纠纷、邻里矛盾引发的冲突优先往民事/治安方向辩护；
- 催收非法债务罪（第293条之一，刑修十一新增）：仅限催收"高利放贷等非法债务"，
  先打债务合法性——合法债务催收不构成本罪；注意从旧兼从轻的时间效力；
- 敲诈勒索罪（第274条）：核心是非法占有目的与胁迫行为；合法维权、有真实请求权基础、
  索赔金额与损失相当的不构成；职业打假/恶意索赔重点打"虚构事实+要挟"因果链；
- 强迫交易罪（第226条）：审查暴力威胁、是否违背真实意愿、情节是否严重，
  正常商业谈判与霸王条款不等于强迫交易；
- 侵犯公民个人信息罪（第253条之一）：信息来源、条数鉴定、违法所得计算均需质证，
  批量信息去重、真伪存疑的作有利于被告人认定；
- 侮辱、诽谤等网络暴力犯罪（第246条等）：自诉案件属性、转发量/点击量证据固定、
  传播行为与被告人的因果关系是质证重点；
- 每个个罪固定输出：入罪要件清单 → 卷宗证据对应表 → 3 个以上辩护切口 →
  时效与既判力审查 → 待补强事项；证据不足的明确写"建议作无罪/存疑不起诉辩护"。

## 十一、37 天黄金救援作战表与分阶段 SOP（v3 新增，把经验变成时间表）

## 十二、四特征量化评分表（定位辩护目标的沟通工具）
四特征各拆 3 个子项共 12 项，每项按卷宗证据三态赋分：成立=2 分、存疑=1 分、
不成立/无证据=0 分，满分 24 分。硬规则优先于分数：任一特征整体不成立，
即不能认定黑社会性质组织，评分仅用于团队内部与客户沟通，不对外作为法律意见。
- 总分 ≤ 8 且至少一个特征为 0 分：主攻第一目标（无罪/不按黑社会处理）；
- 总分 9–15：主攻第二目标（降级恶势力或普通共同犯罪）；
- 总分 ≥ 16：入罪可能性高，主攻第三目标（角色降档＋量刑＋财产刑）；
- 每次评分必须附每项的卷宗页码依据，禁止凭印象打分；评分随补证动态更新。

06不会写代码：把要求说清楚，让 AI 替你搭

本手册里的代理脚本和配置文件，我自己一行代码都没写。做法是把"要什么效果、出问题怎么切换、密钥怎么保护"讲清楚，让 AI 生成，再让它逐段解释给我听。一个好用的四段式需求模板：

  1. 目标与环境：什么系统、要实现什么、监听在哪；
  2. 行为规则：正常时怎样、异常（限流/欠费/失效）时分别怎样；
  3. 安全约束：密钥只读本机文件、日志只留后几位、占位符由本人粘贴；
  4. 运维要求：配置热生效、开机自启、逐段解释、给出验证方法。

第一章的代理、第零章的安装、第三章的本地 OCR，用的都是同一个套路。接数据库、配 MCP 同理：让它生成配置，密钥位置先留 sk_你的KEY 占位符，最后由你本人粘贴。

判断生成结果靠不靠谱让它逐段解释代码意图；检查日志里有没有完整密钥；要求它给出"怎么验证生效"和"出错了看哪个文件"。看不懂的脚本不要放进开机自启。

08上手前最常问的八个问题

Q1　我不写代码，真的能自己搭起来吗？

能。本手册里所有脚本和配置都不是我手写的，而是把要求讲清楚让 AI 生成。你的任务只有两个：会复制粘贴，会把运行结果原样发回去问。卡住时把报错信息完整发给 AI，让它给下一步，不要自己猜。

Q2　11 月 8 日活动结束了怎么办？还能用这套方法吗？

活动只影响价格，不影响方法。活动后可按原价或新的官方活动订阅，第一章的单账号、代理配置完全不变；已经写好的 opencode.json 只需换 Key，不用重搭。

Q3　代理跑起来后，healthz 打不开或提示连接失败？

  • 先确认 start.bat 的黑窗口还开着、没有报错退出（关掉窗口代理就停了）；
  • 确认端口 18234 没被别的程序占用，Python 已正确安装并在 PATH 里；
  • 看同目录 proxy.log 最后几行；把报错整段发给 AI 助手排查，不要只截一句。

Q4　Key 填进去报 401/403？

八成是这三种：Key 复制时多了空格或换行、Key 已被禁用或删除、套餐未生效或已到期。先去控制台重新复制一次完整 Key，再确认套餐状态；代理模式下还会把失效 Key 自动冷却 30 分钟，可在 proxy.log 里看到记录。

Q5　MCP 数据库提示积分/余额不足？

按第二章 2.2 的降级规则走：先用 get_user_balance 查当前账号余额（这个动作不扣积分），不足就切到下一优先级账号；不要同时对多个账号发同一个付费请求，否则会重复扣费。

Q6　AI 还是会"装作读过"材料，怎么治？

回到第三章 3.7 的四把锁：读做分离、分批不抽样、读完复述、结论带出处。再加一条硬约束：让它每轮开头报"已读 x/y"，数字对不上台账就打回。材料本身是扫描件的，先确认 OCR 这一步过了关（3.3、3.4）。

Q7　Skill（技能）到底存在哪、怎么生效？

三种方式按勤快程度选：偶尔用就开工前整段粘贴（第五章 5.1）；某个案件专用，就放进该案件文件夹的 AGENTS.md；想所有任务通用，就存成全局技能文件（如 5.2 表里的 engineering-quality.md）。新存的技能，重开一个会话确认它被读到再正式用。

Q8　真实卷宗到底能不能用云端 AI？

不能直接用。命令行工具不等于本地处理，模型仍在云端。正确顺序是先在本机脱敏（真实信息换代号、词典不出本机），再让云端处理代号文本，成果回本机还原；涉密材料优先全本地、断网方案。脱敏要做到 100%，99% 就等于有 1% 在裸奔，详见 3.5。
